## Method

- Entry points enumerated from `tools/**` (`*.py` containing `__main__`,
  `*.ps1` containing a `param(` block), plus every `hornlab_search/cli.py`
  subcommand, plus the public callables in `hornlab_search/objective/replay.py`
  and the main public API of `hornlab_search/bo/` and `hornlab_search/geometry/`.
- Flags read statically from `argparse` (`add_argument`) / PowerShell `param`
  blocks, and invocation examples taken from module docstrings. No tool was
  executed and no GPU job was run (a night is live).
- `code_map` = the path or its basename appears in `docs/CODE_MAP.md`
  (CODE_MAP often documents a whole `tools/analysis/` package by basename).
- `last_commit` = `git log -1 --format=%cs -- <path>`.
- CSV is LF, one header line plus one row per item.

## Required tools — exact invocations (verified from docstring/argparse)

```
.venv\Scripts\python.exe tools/search_preflight.py CONFIG [CONFIG ...]
.venv\Scripts\python.exe tools/run_campaign_night.py --night runs/nights/<night>.yaml [--dry-run]
.venv\Scripts\python.exe tools/night_status.py [--since-hours 24] [--top 6]
.venv\Scripts\python.exe tools/shape_check.py examples/typologies/<folder>/*.yaml [--brief <yaml>]
.venv\Scripts\python.exe -c "from hornlab_search.objective.replay import replay_run_dir; r=replay_run_dir('runs/<run>', '<design_hash>', brief='examples/briefs/<brief>.yaml')"
```

`replay_run_dir` has no CLI wrapper; the canonical agent path is a one-line
Python call (as used by `tools/analysis/rescore_identity.py` and the
`docs/evidence/*/replay_*.py` scripts). For a CLI, use
`tools/analysis/rescore_identity.py rescore <run dir ...> --brief <yaml> --out <dir>`.

## Invocations not verified (did not execute anything)

1. **Library/API rows (20).** `replay.py`, `bo/*` and `geometry/*` have no CLI.
   Their invocation is a `.venv\Scripts\python.exe -c "from ... import ..."`
   call built from the real function signature; argument names/order are read
   from source, not exercised. Treat them as import recipes, not shell commands.
2. **First-flag-only invocations (63 rows).** These tools have an argparse
   parser but no usage block in the module docstring, so the CSV shows
   `<python> <path> [--first-flag ...]`. The flag names are exact; the required
   value/positional form is not captured. Any row whose invocation ends in
   `[--flag ...]` is in this class (e.g. `tools/analysis/convergence.py`,
   `tools/analysis/sensitivity.py`, `tools/analysis/term_balance.py`,
   `tools/analysis/walls.py`, `tools/analysis/links.py`,
   `tools/geometry/audit_rolled_family.py`, `tools/night_queue/run_bo_arm.py`).
3. **Environment-specific interpreters.**
   `tools/bo_compare/prepare_study.py` documents
   `..\oc-wt\bo-study\bayes-venv\Scripts\python.exe`, a non-canonical former
   worktree path; `tools/geometry/check_sculpted_mesh_fidelity.py` documents
   `scratch\vizenv\Scripts\python.exe`; `tools/render/render_views.py` must run
   in the viz env, not `.venv`.
4. **PowerShell entry points (6).** Invocations are the comment-block examples
   and `param` names, not executed. `queue.ps1`/`refresh_loop.ps1` are normally
   launched through `launch_detached.ps1`.
5. **Docstring copy-paste bug.** `tools/analysis/classify_recipes.py`’s usage
   line names `tools/analysis/catalog.py`; the CSV uses the correct
   `classify_recipes.py` path.

## 10 highest-value tools for the integrator

1. `tools/search_preflight.py` — headroom/sigma/refusal gate before any night;
   the single best “is this search worth GPU time?” answer.
2. `tools/shape_check.py` — CPU-only mesh/envelope/driver check, safe while a
   night runs; replaces `run --dry-run` for shape questions.
3. `tools/run_campaign_night.py` — the night runner itself (sequential jobs,
   hygiene, summary.jsonl); the queue/monitor entry point.
4. `tools/night_status.py` — live two-lane status, row age, lock holder, stalls.
5. `hornlab_search/objective/replay.py::replay_run_dir` — canonical backend-free
   re-score of a stored run under another brief, with identity/parity status.
6. `hornlab-search verify` — re-solve a run’s top designs at verify fidelity
   (the `--run/--top/--designs` path every result passes through).
7. `tools/analysis/rescore_identity.py` — CLI rescore under one score identity +
   frequency noise floor; the practical wrapper around `replay_run_dir`.
8. `tools/analysis/convergence.py` — best-so-far J vs valid-eval index; first
   look at whether a run actually improved.
9. `tools/analysis/sensitivity.py` — per-knob influence on J; explains what a
   search learned and what to pin/narrow next.
10. `tools/night_report.py` — morning report straight from `summary.jsonl` and
    run dirs; the fastest read of what a night produced.

Near-misses worth linking beside them: `tools/analysis/report_day.py` (one spec
→ `REPORT.md`), `tools/atlas/build_atlas.py` (project-wide HTML), and
`tools/data/top_designs.py` (best solved designs per typology/score set).
