## Dossier vs code discrepancies (recorded both)

1. **CD backbone knob ranges.** Dossier §3(d) first pass: `lam_H` 0–1, `lam_V` **0–0.5**,
   `lt` 0.10–0.20, `lr` 0.25–0.35. Code (`_cd_backbone_v1.py:32-34`) allows `bb_h`/`bb_v` **0–1**,
   `bb_throat_frac` **0.05–0.30**, `bb_rollin_frac` **0.15–0.45**, and adds `MAX_BODY_SUM=0.80`.
   Code is wider than the first-pass dossier; the FAMILY_LAWS entry says so.
2. **Klangfilm modules are not the Klangfilm ellipse tool.** `KLANGFILM_ELLIPSE_HANDOFF_2026-11-16.md`
   lists `fc_hz` 480–800, `stretch` 1.15–2.2, `end_frac` 1.0–1.85, `bend_radius_mm` 320–3000,
   `throat_ellipse` 0.3–1.0 — those belong to `tools/geometry/klangfilm_ellipse.py`. The shipped
   `klangfilm_lame` kernel uses different keys/ranges (`fc_hz` 150–3000, `aspect` 1–4,
   `end_frac` 0.3–1.9, `rim_sweep_ratio` ±0.6, `morph_frac` 0.05–0.9). The cards keep them
   separate and do not transfer ranges.
3. **`_rolled_rect_v1` ranges are wider than the study's starting ranges.** The construction study
   gives rect_exponent 8–16 and depth_h_ratio seed 0.68 (initially fixed); the kernel accepts
   [2,16] and [0.5,1.2]. Noted in the cards as "study range" vs "kernel bound".
4. **CD backbone evidence has moved past the dossier.** The dossier status line says rolled `bb_h`
   0.5 passes; the 2026-11-25 evidence adds the keeper `bb_h` 0.65/throat 0.25 and the second-body
   transfer. Both are cited; the evidence is newer, not contradictory.
5. **Frozen-copy SHA in Klangfilm docstrings is stale.** `docs/knowledge/contracts/klangfilm_lame_hv.md`
   records that the `Frozen copy ... SHA256` docstrings do not match the current tools files
   (docstring/import differences only). Card open question notes it.
