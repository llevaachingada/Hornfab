## Editing a running queue (runner change, this session)

`tools/run_campaign_night.py` now re-reads the night file before every job (`tests/test_night_runner_live.py`, 10 tests;
the 54 existing night-runner tests still pass):
- Reorder, insert, remove or change any job that has not started. The next job follows the file; the running job is
  never interrupted.
- A finished id never re-runs. To run a job again, give it a new id.
- A bad edit (half-saved file, YAML error, duplicate id, changed `night`/`lane`) logs `RELOAD FAILED`, and the last
  good plan continues.
- Pause: `New-Item runs\nights\<night>\PAUSE` (or `pause: true` in the YAML). Resume: delete it. While paused, the
  runner keeps re-reading the file, so a reorder made during the pause applies when it resumes.
- Stop after the current job: `runs\nights\<night>\STOP` (or `stop: true`).
- Status: `runs\nights\<night>\queue_state.json` (done / running / pending) and `runs\overnight\queue_<night>.log`.
- Night B is read only when `queue.ps1` reaches it, so it can be edited freely until then.
- `--no-live` restores the old read-once behaviour.
