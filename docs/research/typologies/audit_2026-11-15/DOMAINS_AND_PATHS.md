## Activity and interaction

* Unit normalization is alphabetical by searched key (`design/space.py:1-4, 45-65`; `design/generated.py:167-177`). Linear physical `x = lo + u(hi-lo)`; logarithmic `x = 10^(log10(lo)+u(log10(hi)-log10(lo)))`. `sigma0` is in unit coordinates. The extractor records theoretical asymmetric log steps if encountered; consult the bounds, not parameter name. Both transformations clip, and generated knobs round to 10 decimals (`design/generated.py:170-177`). Distinct out-of-box or sufficiently close vectors can map to the same physical point. Clipping affects seeds normalized from existing designs as well.
* Native `rf` validates seed within all bounds, exact fixed equality, no log bounds, inactive amplitude zero, disjoint relief position intervals, landscape and source geometry (`design/generators/rolled_family.py:216-260`). Radial relief uses H/V weighted amplitudes and `cos(2 psi)^2`; axial uses H/V weighted signed amplitudes and `cos(4 psi)`; both multiply a window and can interact with base shape, throat and outer shell (`rolled_family.py:120-190`). Pinned window positions remain specified even when amplitude is zero: no independent effect at that point. Smooth, radial and axial modes prevent nonzero inactive amplitudes. Zero radial or axial strengths are a common geometric meeting point across different mode recipes, not proof their recipe identities coincide. Relief onset, derivative, centerline, monotonicity, full-body envelope and shell checks can reject combinations inside nominal bounds; independent endpoint checks do not prove the entire box feasible.
* Original rect pucker uses its own start turn and H/V amplitudes, unlike native radial relief; section-pucker start/peak/end station and signed z amplitudes are a different law. Section crown and H-depth scale couple to reconstructed junction, shape and outer body. Nominal width, height and depth are shape inputs, not guarantees of finished full-shell extents. Rect `depth_h_ratio` couples per-plane depth, not two freely independent lengths.
* Native ATH azimuth law combines `a_deg`, cosine amplitude/power and superformula amplitude (`design/families.py:100-110, 134-166`); an amplitude at zero makes its shape parameters dormant. In core and ext-throat configs morph target 0 makes morph target dimensions inactive even though pinned values remain in seed. Extended throat length and angle determine the actual driver connection; seed `r0_mm`/`a0_deg` should not be interpreted as independently searched throat dimensions (`search/evaluate.py:367-383`). Morph target and corner/rate parameters interact in `hl__osse_rrect_morph`. The full joint parameter box is not certified by this inventory.
* Biradial plane closure requires the actual radius/length/angle combination to be valid; the revised config describes coupled box choices but that is not a proof across every continuous point or an acoustic result. In Hypex, H/V mouth radii, length and T jointly define curves. Crowe-X OSSE angle, length, termination, lip and superformula jointly determine geometry; roll and shape parameters do not guarantee independent coverage/termination effects. R-OSSE depth is derived rather than independently searched; its W/H/angles/termination interact. Iwata aspect stretch and stop combine with the base march. No universal claimed acoustic effect is inferred from knob labels.

## Shared path and identity

* Native rolled-family recipes pin schema, implementation digest (master plus both private kernels and reference), categorical kind/mode, driver radius/angle, grid resolution, thickness and knobs; loading compares current digest and driver (`rolled_family.py:27-37, 72-92, 195-212`). `resolve_grid` constructs and validates both sheets (`rolled_family.py:140-200`); native grid dispatch, meshing and envelope use this resolver (`grid.py:2613-2621, 2690-2704, 2804-2807`; `mesh/grid_build.py:80`). `GeneratedSpace.knobs_for` rebuilds a persisted family recipe and compares design hash (`generated.py:223-235`). These code paths support consistent replay, but this audit did not execute an end-to-end equality test or revalidate saved artifacts. Pinning does not itself pin every mesher/solver dependency or certify mesh/source triangles.
* Legacy bridge `install()` replaces dispatch in the current process only (`tools/geometry/rolled_rect_cli.py:107-150`). Its recipe pins schema/digest/driver and validates on load (`:64-78, 117-132`). Section and section-pucker wrappers supply their own exterior via mesh resolver monkeypatch (`crowe_panel_cli.py:50-71`; `section_pucker_cli.py:50-71`); R-OSSE wrapper rebinds bridge (`rosse_rect_cli.py:29-38`). A cold process must install the matching wrapper before loading/replaying; a stock CLI or worker is not equivalent merely because GUI can preview it. The exact path, wrapper version, brief and dependencies must travel with an artifact. GUI bridge mapping lists R-OSSE, rect, pucker rect, and panel but not `section_pucker` (`gui/data.py:3210-3217`); bridge preview runs in a fresh process (`:3222, 3347-3352`, `tools/geometry/gui_preview.py:36-57`). * CMA bounds unit coordinates (`search/cma.py:534, 559`).
