# Top GPU-solved designs, by typology and score set

This directory is a **generated, self-describing export** of the best GPU-solved horn designs in
the local `runs/` tree. It exists because `runs/` is git-ignored: a cloud or review agent cannot
read the original `search.ndjson`, `metrics.json` or `response.npz` files, but it can read this
bundle.

## Files

| File | Contents |
|---|---|
| `top_designs.csv` | One row per selected design. Flat, spreadsheet-friendly: typology, score set, J, dimensions, all scalar geometry parameters (`param_*`), all objective terms (`term_*`), all metric scalars (`metric_*`), provenance, and the acoustic-array key. 160 columns, union of every typology's knobs; blank means the typology does not use that knob. |
| `top_designs.json` | The full manifest. Shared `score_configs` (objective block + weights + target + brief), shared `runs` (config name/SHA/path, brief file, toolchain, command), `groups` (census, best J, score/target hashes, modes), and `designs` (nested params/generator/cad/mounting, terms, per-frequency metric arrays, dimensions, solve provenance, acoustic-key). |
| `top_designs_acoustics.npz` | The stored acoustic response for every selected design, compressed (`numpy.savez_compressed`). Keys are `<acoustics_id>__<array>`; the `acoustics_id` is in the CSV/JSON. Arrays: `freqs_hz`, `h_angles_deg`, `v_angles_deg`, `spl_h_db`, `spl_v_db`, `balloon_dirs`, `spl_balloon_db`, `z_throat`. SPL/angle/direction arrays are `float32`; `z_throat` is `complex128`. |

`acoustics_id` is a stable 16-hex SHA of `(design_hash, mesh_hash, solve_hash)`, so a regenerated
bundle without new solves keeps the same keys. Every selected design in this snapshot has arrays
(`missing_design_dirs: 0`); if a future top design has no local response, `acoustics_id` is `null`
and the JSON says so.

## Ranking and grouping

- **J is minimised.** `rank=1` is the **lowest** objective in its group. The CSV/JSON field is
  `objective`; the README and manifest call the ordering "ascending objective (lower is better)".
- **Score set = objective version** (`v1`, `v2`, `v3`, `v4`, `v5`, `v6`, `v7`, `v9`, `v10`, or
  `unversioned`). This follows the repository rule *never rank J across objective versions*.
  A single version group can contain several briefs/targets: use `score_config_sha` and
  `target_sha` (or regenerate with `--group-by score-config`) when you need a strictly
  same-brief comparison.
- **Rows with no recorded objective version** are kept as `unversioned` (pre-provenance rows).
  They are a real score set here, not v1: `version_source` is `missing`. Regenerate with
  `--exclude-unversioned` to drop them.
- **Typology** is `typology_name(generator, family)` from `hornlab_search.dataset.record`, then
  normalised for grouping: the redundant `typology:` prefix is dropped, and `OSSE` / `R-OSSE` /
  `ICW` / `FREEFORM` are upper-cased so generated (`typology:osse`) and legacy family-only
  (`OSSE`) rows are one typology. The raw helper output is `typology_label`.
- **GPU only.** A row is accepted when its own `backend == beat_cuda` or `lane == gpu`, falling
  back to the owning `run.json` for older rows. CPU rows are excluded. The manifest records the
  filter and the `not_gpu` count.
- **Dedupe.** The same physical solve (`design_hash|mesh_hash|solve_hash`) inside one score set is
  collapsed to its best (lowest) J. The same physical solve can appear once per score set because
  a stored solve may be re-scored under another objective version.
- **top 10 per group.** Groups with fewer than 10 scored solves export what exists (hence
  `n_selected < 10` for small early sets). `n_scored` is the number of unique scored physical
  solves in the group before the top-N cut.

## Dimensions

`bbox_m` is the mesher's stored fundamental-domain bbox. `bbox_quadrant_mm` is its span in mm.
`bbox_full_est_mm` (and `mouth_width_mm_est`, `mouth_height_mm_est`, `depth_mm_est`) doubles each
axis listed in `symmetry_plane`:

- `yz` (symmetry plane x=0) → double x
- `xz` (symmetry plane y=0) → double y

This is an **estimate of the full horn extent**, not a measured mouth outline. The raw bbox is
always present. `depth_mm_est` is the z span; axis conventions are family-specific (the mesher
builds the axis along +z for the usual horn families, but grid/CAD recipes should be checked in
the raw bbox). `area_m2_quadrant` is the stored fundamental-domain surface area; `area_m2_full_est`
multiplies it by 2 per symmetry plane.

Throat geometry is in the parameter block (`r0_mm`, `throat_ext_length_mm`, `throat_ext_angle_deg`,
etc. as applicable), not inferred from the mesh.

## Full acoustic data

`top_designs_acoustics.npz` contains the analysable stored response:

- H/V polar SPL cuts at the solved angles (`spl_h_db`, `spl_v_db`, `h_angles_deg`, `v_angles_deg`)
- the full balloon SPL (`spl_balloon_db`, `balloon_dirs`)
- the complex throat impedance (`z_throat`)
- the frequency axis (`freqs_hz`)

`top_designs.json → designs[].metrics` also carries the stored metric arrays
(`bw_h_deg`, `bw_v_deg`, `di_db`, `ripple_h_db`, `ripple_v_db`, `on_axis_db`, `z_throat_real`)
and all metric scalars (`di_mean_db`, `ripple_mean_db`, `flatness_db`, `f11_hz`, ...).

Raw complex pressure arrays (`p_h`, `p_v`, `p_balloon`), channel pressures and the impedance
matrix are **not** copied: the SPL magnitude response + balloon + throat impedance are the
analysis surface, and including every complex array would multiply the committed size. The local
`runs/<run>/designs/<design_hash>/response.npz` remains the provenance source if phase-level work
is ever needed.

## Cloud-agent quickstart

```python
import json
import numpy as np
import pandas as pd

df = pd.read_csv("docs/top_designs/top_designs.csv")
manifest = json.load(open("docs/top_designs/top_designs.json", encoding="utf-8"))
acoustics = np.load("docs/top_designs/top_designs_acoustics.npz")

# Best v10 OSSE design in this export
row = df[(df.typology == "OSSE") & (df.score_set == "v10")].sort_values("objective").iloc[0]
print(row[["rank", "objective", "design_hash", "param_L_mm", "mouth_width_mm_est"]])

aid = row.acoustics_id
freqs = acoustics[f"{aid}__freqs_hz"]
balloon = acoustics[f"{aid}__spl_balloon_db"]      # (n_freqs, n_dirs)
h_cut = acoustics[f"{aid}__spl_h_db"]              # (n_freqs, n_h_angles)
z_throat = acoustics[f"{aid}__z_throat"]           # complex128

# Same-brief comparisons only:
same_brief = df[df.score_config_sha == row.score_config_sha]
```

The JSON is the authority for nested blocks; the CSV is a flat convenience view. Prefer
`score_config_sha` + `target_sha` for comparing designs that were scored against the same brief.

## Regenerating

From the repository root (read-only over `runs/`; writes only under `--out`):

```powershell
# default: top 10 per typology+objective-version, includes unversioned, writes all three files
.venv\Scripts\python.exe tools\data\top_designs.py

# strict same-brief grouping
.venv\Scripts\python.exe tools\data\top_designs.py --group-by score-config

# manifest only (fast; no NPZ)
.venv\Scripts\python.exe tools\data\top_designs.py --no-acoustics

# drop pre-provenance rows
.venv\Scripts\python.exe tools\data\top_designs.py --exclude-unversioned
```

Offline tests (synthetic run tree, no GPU/solver):

```powershell
.venv\Scripts\python.exe -m pytest tests\test_tools_data_top_designs.py -q
```

## Caveats

- **Do not rank J across score sets.** v4/v5/v6/v7/v9/v10 are different scoring functions, and
  the objective config/target can change inside one version.
- **Selected designs are not a random sample.** They are the top of each group; use the full
  per-run `search.ndjson` (local) or the dataset store for distributions.
- **Data provenance:** each design points at its source `run_rel` and `config_sha`; the
  original run tree is local-only provenance, not part of this bundle.
- **Live tree:** a running night can add solves after the snapshot timestamp. Regenerate to
  refresh; the `generated_utc` and `repo_head` in the JSON identify this snapshot.
