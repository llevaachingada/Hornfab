# Staged vs joint A/B — crease__core_law

Equal-budget comparison of hierarchical block search vs one joint CMA-ES run,
per the staged-search recommendation (2026-10-31).

| Arm | Config | Budget | Active knobs |
|---|---|---|---|
| Joint (control) | `joint__crease_core_law.yaml` | 60 | all joint-searchable keys |
| Stage A (macro) | `stageA_macro__crease_core_law.yaml` | 20 | `L_mm`, `a_deg`, `n`, `s`, `k` |
| Stage B (shape) | `stageB_shape__crease_core_law.yaml` | 20 | `az_*` polish + `morph_corner_mm`/`morph_rate`/`morph_fixed` |
| Stage C (polish) | generated by the tool from B's `best.json` | 20 | A∪B, boxes ±12 % around B, `sigma0` 0.06 |

Total staged budget = 60 = joint. Stage B's seed (and pins) are rewritten from A's
`best.json`; Stage C is rewritten from B. Do not hand-edit Stage C — the harness owns it.

Shipped YAMLs keep `solve.backend: beat_cuda` + `cuda_fused: true` for the Windows GPU box.
The harness rewrites the backend for the machine you are on (see below).

## Run — Windows CUDA box

```powershell
.\.venv\Scripts\python.exe tools\run_staged_search.py `
  --out runs\staged_ab_2026-10-31 --both
```

`--backend auto` (default) → `beat_cuda`. One GPU job at a time.

## Run — Apple Silicon Mac (Metal)

Needs a project venv with the pinned stack (`requires-python >=3.11,<3.14` — use 3.12 or 3.13,
not 3.14), Julia via juliaup, and Xcode CLT for Metal.

```bash
# once: create/activate the venv and install (from repo root)
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev,crosscheck]"

# staged A/B — auto selects beat_metal on Darwin and clears cuda_fused
python tools/run_staged_search.py --out runs/staged_ab_2026-10-31 --both
```

Force a backend explicitly:

```bash
python tools/run_staged_search.py --backend beat_metal --out runs/staged_ab_mac --both
python tools/run_staged_search.py --backend beat_cpu --out runs/staged_ab_cpu --both   # slow fallback
```

Sanity before a long search:

```bash
python -m hornlab_search.cli doctor
python -m hornlab_search.cli search \
  --config examples/typologies/staged_ab_2026-10-31/stageA_macro__crease_core_law.yaml \
  --backend beat_metal --mode screen
```

(`--backend` on the CLI overrides the YAML; the harness also rewrites emitted configs so
`cuda_fused` is false off CUDA.)

Metal results are a **different solver path** from CUDA — do not mix them into the same
leaderboard or dataset group until a Mac↔4060 A/B is within ~0.2 dB (NEXT_DEV_PRIORITIES P3).

## Dry-run / synthetic (no solver)

```bash
python tools/run_staged_search.py --dry-run --out runs/staged_ab_check
python tools/run_staged_search.py --synthetic --out runs/staged_ab_check
```

Report: `runs/staged_ab_*/COMPARE.md` (and `COMPARE_SYNTHETIC.md` for the toy landscape).
`COMPARE.md` and `plan.json` both list **active vs fixed/pinned** knobs per stage
(`knob_schedule`).
